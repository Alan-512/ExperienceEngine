## Context

Harm recovery is not equivalent to a single skip. The causal sequence begins with an eligible node, actual treatment delivery, deterministic harmful outcome, authoritative harmed evidence, and a production governance transition. A later equivalent opportunity then tests whether the harmful node is no longer delivered.

## Decisions

### 1. Use two predeclared opportunities

`harm_exposure` is expected to inject; `recovery_recheck` is expected to skip after authoritative harm in treatment.

### 2. Production authority owns state mutation

The harness may invoke the same host/runtime feedback path used by users and may read resulting records. Direct SQL updates of node counters, state, delivery state, attribution, or review events invalidate the block.

### 3. Preserve causal arm divergence

Forced holdout runs the pipeline but does not deliver the initial guidance, so it does not receive invented harm. No-EE contains no ExperienceEngine state. Divergence after treatment exposure is part of the measured mechanism.

### 4. Fresh sessions isolate the recheck

The recovery prompt uses a fresh host session and a reset workspace so suppression is attributable to governed ExperienceEngine state rather than model conversation context or leftover files.

### 5. Supplemental metric only

The initial protocol reports harm-recovery rate as supplemental evidence. It does not silently change the frozen minimum public scorecard or authorize support/readiness claims.

## Acceptance

- Deterministic fixtures prove actual harm, authoritative feedback, non-live transition, and later suppression.
- Missing feedback, direct state edits, absent transition evidence, repeated harmful delivery, or reused host context fail closed.
