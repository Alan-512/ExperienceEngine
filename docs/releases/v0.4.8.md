# ExperienceEngine v0.4.8

This release records the runtime-boundary extraction, status UX, path isolation, and robustness changes prepared after `v0.4.7`.

## Changes

- Extracted a shared `PromptDecisionPipeline` so lightweight shared-MCP prompt lookup and the full runtime prompt path use the same candidate loading, repo-policy evaluation, delivery suppression, scorecard, and `InjectionEvent` persistence logic.
- Extracted `TraceCaptureService` from the full runtime so trace normalization, trace provenance summaries, and opt-in diagnostic trace capsule persistence have an explicit runtime boundary without changing default narrow persistence behavior.
- Extracted `HybridPostmortemService` from the full runtime so async posttask review, provider fallback handling, artifact persistence, and accepted node review writeback are isolated behind a dedicated runtime boundary.
- Extracted `AttributionWritebackService` from the full runtime so automatic attribution rows, trajectory attribution metadata, record-only diagnostic rows, and shadow-probe quarantine writeback are isolated behind a dedicated runtime boundary.
- Extracted `InjectionOutcomeService` from the full runtime so injected-node feedback updates, injection event resolution, same-scope promotion, cross-scope portable validation evidence, and attribution writeback orchestration are isolated behind a dedicated runtime boundary.
- Extracted `PosttaskRouteService` from the full runtime so posttask hybrid rollout resolution, route signal construction, candidate-signal derivation, and postmortem-already-recorded checks are isolated behind a dedicated runtime boundary.
- Extracted `BackgroundLearningRuntime` from the full runtime so pending background learning tracking, candidate persistence scheduling, and async postmortem invocation after candidate persistence are isolated behind a dedicated runtime boundary.
- Extracted `HygieneGovernanceRuntime` from the full runtime so autonomous hygiene scheduler creation, optional LLM planner resolution, enqueue/drain task tracking, and governance failure logging are isolated behind a dedicated runtime boundary.
- Extracted `ToolEventRecoveryRuntime` from the full runtime so tool event deduplication, tool-call-id keyed orphan result caching, and finalize-payload tool result recovery are isolated behind a dedicated runtime boundary.
- Extracted `RuntimeWorkerFactory` from the full runtime so lazy construction and memoization of the LLM learning gate, distillation queue worker, and hybrid worker client are isolated behind a dedicated runtime boundary.
- Extracted `RuntimeSessionStore` from the full runtime so session map ownership, session creation/reset, host context merge semantics, and stable episode id resolution are isolated behind a dedicated runtime boundary.
- Extracted `FinalizeTaskCoordinator` from the full runtime so finalized input construction, transaction-scoped persistence, trace persistence, injection outcome writeback, posttask route resolution, background learning scheduling, finalize telemetry, and posttask governance wakeup are isolated behind a dedicated runtime boundary.
- Extracted `ToolResultRuntime` from the full runtime so host tool result normalization, persisted tool result trace capture, tool event recovery writeback, and tool-result telemetry logging are isolated behind a dedicated runtime boundary.
- Extracted `HostLifecycleRuntime` from the full runtime so host event session merging, prompt trace capture, prompt-time governance wakeup, and prompt decision pipeline invocation are isolated behind a dedicated runtime boundary.
- Added Antigravity to `ee status` installed-host and interaction-readiness reporting, matching the existing `ee doctor antigravity` support.
- Split `ee status` into a concise default progress view and a detailed `ee status --verbose` view.
- Personalized first-value next-step guidance with recent learning rejection reasons.
- Isolated explicit `homeDir` test/runtime paths from ambient `EXPERIENCE_ENGINE_HOME`, `EXPERIENCE_ENGINE_DATA_DIR`, and `EXPERIENCE_ENGINE_CAPTURE_DIR` values unless an env object is passed explicitly.
- Hardened slower Windows/SQLite test cases with explicit per-test timeouts so the full concurrent suite does not fail on default 5-second timing under load.
- Hardened Claude Code doctor install-state parsing so empty or malformed install state JSON does not crash diagnostic reporting.
- Hardened settings store reads so empty or malformed `settings.json` files are treated as absent and later settings writes can recover cleanly.
