# ExperienceEngine v0.5.0

**Status:** published; npm runtime validation passed, ClawHub live-host acceptance failed and requires a new patch artifact.

This release introduces the package-local OpenClaw production learning runtime and the distribution evidence needed to validate the exact artifacts users install. The evidence-bound artifact is now published to npm, GitHub Releases, and ClawHub. Exact npm validation passed on OpenClaw `2026.7.1`; ClawHub byte/closure validation passed but its native install omitted required runtime dependencies and failed plugin import. Full production background-learning support is therefore not claimed, and the separate S8 benchmark/quality gate remains pending.

## Runtime authority foundations

- Added canonical ExperienceEngine home and package-generation identity shared by plugin, supervisor, worker, and operator paths.
- Added embedded runtime closure manifests and create-once integrity binding for package/runtime assets.
- Added SQLite compatibility policy, schema metadata, single-owner migration authority, and fail-closed plugin modes.
- Added launch authorization, launch-attempt binding, supervisor and worker leases, fencing tokens, lifecycle terminalization, and split-brain protection.

## Configuration, routing, and semantic queue

- Added immutable configuration generations, provider/profile validation, integrity-bound current pointers, and crash-atomic route authority.
- Added capability-specific runtime route projection with fail-closed invalidation.
- Added fenced semantic queue claim, renewal, completion, interruption recovery, deterministic failure classes, separate retry counters, and bounded provenance.
- Preserved the `custom-shadow-only-v1` delivery cap for unbenchmarked custom semantic origins.

## OpenClaw production activation

- Added package-local supervisor and worker entrypoints with OpenClaw-native service lifecycle integration.
- Added explicit activation preparation and initialization commands, exact-revision compare-and-swap behavior, idempotent replay, and current handshake authority.
- Connected the production semantic queue worker to the validated runtime route while rejecting stale-authority output.
- Added strict `ee verify openclaw-production` behavior and separate `interaction_active`, `learning_runtime_active`, and `production_learning_ready` projections.

## Distribution and host validation

- Made the embedded runtime closure manifest the production packaging authority and added staged/final tarball closure validation.
- Added immutable signed install attestations for local-pack, host-native, published npm, and published ClawHub origins.
- Made OpenClaw install, update, repair, interrupted update, rollback, and security-approval handling transactional and explicit.
- Added independent npm and ClawHub artifact download/materialization/inspection validators.
- Added installed-artifact smoke validation and a separate real OpenClaw host runner covering plugin installation, Gateway authentication, activation commands, a real agent turn, protected queue completion, stale-output rejection, restart recovery, and terminal shutdown evidence.
- Declared startup activation in the OpenClaw plugin manifest so lazy-loading hosts register the package service and native commands before agent routing.
- Shared one deferred package-local runtime across OpenClaw startup and command registries, waited for the real service projection before activation, and migrated legacy agent credentials into the host's SQLite auth store only inside isolated validation state.
- Passed local-pack real-host preflight with OpenClaw `2026.4.1` on Linux x64 under WSL and native Windows x64.
- Passed the same local-pack real-host preflight after upgrading the WSL host to OpenClaw `2026.7.1` with Node `24.18.0`, including a real model turn and full restart/shutdown authority evidence.
- Added native Windows `.cmd` resolution, authenticated direct Gateway RPC, and an stdin-to-`SIGINT` bridge so foreground Gateway shutdown reaches graceful plugin-service drain and terminal authority release.

## Documentation and support boundaries

- Updated README, Chinese README, user guide, release notes, architecture documentation, and the OpenClaw runtime support matrix to distinguish routine interaction from production background-learning readiness.
- Kept `artifact_runtime_validated` separate from `support_claim_allowed`.
- Full support claims remain blocked until a remediated ClawHub patch artifact passes its independent published-channel and required platform gates, followed by the S8 matched-block benchmark/quality gate.
