# ExperienceEngine v0.1.2

## Installation Productization

ExperienceEngine no longer treats the `ee` CLI as the public first-install entrypoint.

This release instead positions installation as a host-native concern and keeps `ee` focused on post-install operations like validation, repair, status, and feedback.

### New CLI Surface

- `ee doctor`
  - now supports a no-argument consolidated health summary
- `ee repair`
  - now supports a no-argument repair summary
- `ee status`
  - prints a compact product-facing environment summary

### Host Integration Model

Host wiring remains host-specific:

- `Codex` -> MCP
- `Claude Code` -> hooks + MCP, with marketplace/plugin packaging still pending
- `OpenClaw` -> plugin/runtime integration

The shared `ee` CLI is now the operational surface after installation, not the public installation surface itself.

Current one-step host-native surfaces now documented:

- `openclaw plugins install experienceengine`
- `codex mcp add experienceengine --env EXPERIENCE_ENGINE_HOME=$HOME/.experienceengine -- npx -y experienceengine codex-mcp-server`

### Packaging

The published package remains prepared for direct global CLI installation without requiring a repository checkout or local build. That global package is primarily intended for validation, repair, status, inspection, and advanced operator workflows.
