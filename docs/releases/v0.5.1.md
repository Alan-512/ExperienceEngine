# ExperienceEngine v0.5.1

**Status:** published to npm, GitHub Releases, and ClawHub; exact npm and ClawHub artifacts passed published live-host runtime validation. Public support claims remain gated on quality/benchmark publication evidence.

This patch release repairs the ClawHub-native installation failure found after `v0.5.0` publication. The npm channel continues to publish the full ExperienceEngine package and lets OpenClaw's npm locator install declared dependencies. The ClawHub channel now uses a deliberately reduced OpenClaw archive built from the same committed source boundary, with its required runtime dependencies materialized as ordinary files.

## ClawHub packaging repair

- Reused the generated runtime closure manifest as the sole authority for the reduced OpenClaw package.
- Materialized `@modelcontextprotocol/sdk` and `zod` in a clean npm staging directory instead of packing pnpm workspace links.
- Declared those packages as `bundledDependencies` in the reduced ClawHub manifest.
- Disabled dependency lifecycle scripts, development dependencies, peer installation, audit/funding calls, and binary links during staging.
- Removed the previous manual-tar branch and always packs the reduced archive through npm package semantics.
- Rejects symbolic links in staging, rejects link entries in the tarball, and revalidates the unpacked closure and dependency imports.
- Records `@huggingface/transformers` as an explicit optional runtime dependency because local embeddings remain an operator-installed feature rather than part of the default runtime dependency graph.

## Release candidate artifacts

`v0.5.1` deliberately produces two channel artifacts from one clean committed source boundary:

- npm: the full `@alan512/experienceengine` package for the npm-native dependency installation path.
- ClawHub: the reduced OpenClaw runtime closure with link-free bundled production dependencies.

The exact filenames, sizes, hashes, npm integrity values, source commit, closure digest, and package build id are written to `.tmp/release-candidate-v0.5.1/candidate-manifest.json` after all tracked changes are committed. That external manifest is release evidence and is not embedded here because changing this note would change the artifacts.
